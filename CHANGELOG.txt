Newest version on top. Each entry lists what changed since the

----------------------------------------------------------------
Version: 2026-07-10
----------------------------------------------------------------

Focus: pediatric in-hospital case fatality + interactive dashboard.

SCRIPTS
  - 08_build_consolidated_base.R: added the 0-14 in-hospital death
    count and in-hospital case-fatality rates (all ages and 0-14).
    Age 0-14 is now flagged once (is_0_14) in the SIH aggregation
    and reused for both the admission and death counts.

NEW COLUMNS IN THE CONSOLIDATED BASE (3)  ->  70 to 73 variables
  - sih_n_obitos_hosp_0_14         (in-hospital deaths, ages 0-14)
  - taxa_letalidade_hosp           (case fatality %, all ages)
  - taxa_letalidade_hosp_0_14      (case fatality %, ages 0-14)
    Case fatality = deaths among admissions x 100; NA when there
    were no admissions.

DASHBOARD (new)
  - dashboard/: local Shiny app (app.R) to explore the data —
    an aggregated municipal overview (choropleth map, time series,
    ranking, KPIs, table) and a microdata drill (SIH/SINAN/SIM/
    SISAGUA, lazy arrow filtering). Reads only resultados/; no
    server, no network at runtime. setup_geo.R caches the SP map
    geometry once (dashboard/data/sp_munis.rds). See dashboard/README.md.

DOCUMENTATION
  - DATA_DICTIONARY_BASE.md: documented the 3 new variables,
    renumbered (now 73), and added a note that case fatality is
    per municipality-year (pool counts for aggregate rates).

DATA NOTE
  - In-hospital deaths, ages 0-14: 88 of 14,384 admissions
    (case fatality 0.61%); all ages 2,505 of 76,527 (3.27%).

OUTPUT IMPACT
  - resultados/base_consolidada_sp_2014_2024.parquet: 70 -> 73
    variables. All previously existing columns and values unchanged.

Version: 2026-07-09
----------------------------------------------------------------

Focus: pediatric (age 0-14) health outcomes. The existing
taxa_hosp_100k / taxa_notif_100k / taxa_obitos_sim_100k were
computed over ALL ages; an analysis restricted to ages 0-14
needs age-specific numerators and denominators.

SCRIPTS
  - 08_build_consolidated_base.R: added 0-14 counts to the SIH,
    SINAN and SIM aggregations, plus three pediatric rates. The
    age filter is applied at aggregation, not at download, so the
    all-age columns are preserved. Age coding per system:
        SIH   COD_IDADE %in% c("Dias","Meses")
              | (COD_IDADE == "Anos" & as.integer(IDADE) <= 14)
        SINAN NU_IDADE_N <= 4014   (DATASUS coded age)
        SIM   as.integer(IDADEanos) <= 14
    No re-download needed: the age fields were already retained in
    the individual-level parquets (resultados/SIH, SINAN, SIM), so
    only script 08 was re-run.

NEW COLUMNS IN THE CONSOLIDATED BASE (6)
  - sih_n_hosp_0_14, sinan_n_notif_0_14, sim_n_obitos_0_14
  - taxa_hosp_0_14_100k, taxa_notif_0_14_100k,
    taxa_obitos_sim_0_14_100k
    (pediatric counts over the pop_0_14 denominator)

DOCUMENTATION
  - DATA_DICTIONARY_BASE.md: documented the 6 new variables and
    the per-system age-coding rules; also added the 5 racial
    composition variables (pct_branca..pct_indigena, from the
    2026-06-11 update) that had not yet been listed, and
    renumbered the dictionary (now 70 variables).

DATA NOTE
  - Pediatric share of the 2014-2024 SP cohort: hospitalisations
    14,384 / 76,527 (18.8%); notifications 71,018 / 464,602
    (SINAN, 15.3%; 4 records coded to municipality "350000",
    unspecified, are excluded by the municipal spine, exactly as
    for the all-age column); deaths 87 / 6,564 (1.3%).

OUTPUT IMPACT
  - resultados/base_consolidada_sp_2014_2024.parquet: 64 -> 70
    variables. All previously existing columns and values are
    unchanged.

Version: 2026-06-15
----------------------------------------------------------------

Focus: IVS (Social Vulnerability Index) — clarified how the
single municipal value is selected, and made the pipeline
self-explanatory. No values in the consolidated base changed.

DOCUMENTATION
  - DATA_DICTIONARY.md (IVS section): corrected the description
    of the file grain. The multiple rows per municipality are
    demographic breakdowns by race (label_cor: Branco / Negro /
    Total Cor) x sex (label_sexo: Homem / Mulher / Total Sexo),
    each split by household situation (label_sit_dom) — NOT
    sub-municipal weighting areas, as previously stated.
  - METHODS.md (Section 5, IVS): added "Row structure and
    municipal aggregation" explaining the race x sex grid, why
    the overall value is the "Total Cor x Total Sexo" cell, and
    a reproducibility note.
  - DATA_DICTIONARY_BASE.md (IVS): added a note that each IVS
    value is the overall "Total Cor x Total Sexo" municipal cell,
    not a racial/sex subgroup.

SCRIPTS
  - 07_build_outputs.R: IVS_VARS now retains label_cor and
    label_sexo, so the output parquet keeps the demographic
    stratifiers.
  - 08_build_consolidated_base.R: replaced the maximum-population
    heuristic with an explicit filter
        label_sit_dom == "Total Situação de Domicílio"
        & label_cor  == "Total Cor"
        & label_sexo == "Total Sexo"
    plus a guard that aborts if more than one row per
    municipality remains. Result is identical to the previous
    approach (verified: 645/645 municipalities, 0 differences in
    the ivs value).

ACTION REQUIRED IF RE-RUNNING THE PIPELINE
  - Run 07_build_outputs.R BEFORE 08_build_consolidated_base.R.
    Script 08 now depends on the label_cor / label_sexo columns
    added to the IVS parquet by script 07.

OUTPUT IMPACT
  - resultados/base_consolidada_sp_2014_2024.parquet is unchanged
    (same 7,095 rows x 64 variables, same IVS values). Only the
    selection logic and documentation were clarified.
